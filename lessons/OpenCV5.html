После уроков 1–4 у нас есть чистая бинарная маска: белое там, где «наш» цвет или граница. Но маска — это просто миллион пикселей. Роботу нужны ответы на вопросы: сколько объектов, где каждый из них, какого размера и какой формы. Сегодня превращаем пиксели в объекты, выводим формулы площади и центра масс и делаем из них команду для моторов.

1. Связные области: от пикселей к объектам

Соседи пикселя. У пикселя (x, y) есть 4 соседа по сторонам (вверх, вниз, влево, вправо) и ещё 4 по диагоналям.
4-связность: соседями считаются только 4 по сторонам. 8-связность: все 8.
Связная область (компонента) — максимальное множество белых пикселей, в котором из любого пикселя можно дойти до любого другого, шагая только по белым соседям.

От выбора связности зависит ответ. Диагональная линия из 5 пикселей при 4-связности — это 5 отдельных объектов (пиксели касаются только углами), а при 8-связности — один. На практике для объектов используют 8-связность.

Как размечают области. Проходим картинку построчно. Встретили белый пиксель без метки — даём ему новый номер и «заливаем» (обходом в ширину) всех его белых соседей, их соседей и так далее. Когда заливка закончилась, область размечена; продолжаем сканирование. OpenCV делает это сразу со статистикой:

n, labels, stats, centroids = cv2.connectedComponentsWithStats(mask, connectivity=8)
# n - число меток ВКЛЮЧАЯ фон (метка 0); labels - матрица меток того же размера, что маска
# stats[i] = [x, y, w, h, area] - рамка и площадь области i; centroids[i] = (cx, cy)

2. Контур

Граничный пиксель — белый пиксель, у которого хотя бы один из 4 соседей чёрный (или который стоит на краю кадра).
Контур — упорядоченная замкнутая цепочка граничных пикселей, полученная обходом объекта по краю. Контур хранится как список координат (x, y), а не как картинка, поэтому с ним удобно считать: площадь, периметр, форму.

Алгоритм обхода (трассировка Мура)

  1. Сканируем картинку построчно сверху вниз, слева направо. Первый встреченный белый пиксель s — стартовый. Слева от него точно чёрный (иначе мы бы встретили его раньше): запоминаем этого чёрного соседа как «откуда пришли» b.
  2. Стоя в текущем пикселе p, перебираем его 8 соседей по часовой стрелке, начиная с b. Первый белый сосед — следующий пиксель контура. Чёрный сосед, проверенный прямо перед ним, становится новым b.
  3. Повторяем, пока не вернёмся в s и не захотим сделать тот же первый шаг ещё раз.

Каждый шаг — одно из 8 направлений. Если записать направления числами, получится цепной код Фримена: 0 — вправо, 1 — вправо-вверх, 2 — вверх, 3 — влево-вверх, 4 — влево, 5 — влево-вниз, 6 — вниз, 7 — вправо-вниз. Квадрат из 3×3 пикселей при обходе по часовой стрелке даёт код 0 0 6 6 4 4 2 2.

OpenCV использует более общий алгоритм Сузуки–Абе (1985): та же идея обхода, но он одновременно различает внешние контуры и контуры дырок и строит из них дерево (иерархию).

3. findContours в OpenCV

contours, hierarchy = cv2.findContours(mask, mode, method)
cv2.drawContours(img, contours, -1, (0, 255, 0), 2)    # -1 - все контуры; толщина -1 - залить
  • mask — одноканальная 8-битная картинка; всё ненулевое считается белым. Обычно это результат inRange, threshold или Canny, почищенный морфологией.
  • contours — список массивов формы (N, 1, 2); каждая точка — это (x, y), то есть сначала столбец, потом строка, наоборот по сравнению с индексацией img[y, x].
  • В OpenCV 3 функция возвращала три значения (image, contours, hierarchy), в OpenCV 4 и новее — два. Старый код из интернета падает именно на этом.

Иерархия — массив формы (1, N, 4), где для каждого контура записано [следующий, предыдущий, первый ребёнок, родитель] на том же уровне; −1 означает «нет». Контур с родителем — это дырка (или объект внутри дырки).

Сжатие точек (method)

CHAIN_APPROX_NONE хранит каждый граничный пиксель. CHAIN_APPROX_SIMPLE сжимает прямые горизонтальные, вертикальные и диагональные участки до концевых точек. Квадрат 5×5: 16 точек против 4 — [[2,2],[2,6],[6,6],[6,2]]. Для площади и центра результат одинаковый, памяти меньше.

Контур проходит через центры крайних пикселей. Поэтому квадрат из 5×5 = 25 пикселей имеет контур со стороной 4: contourArea = 16, периметр = 16. Площадь контура всегда меньше числа пикселей. Почему именно на столько, выведем в разделе 6.

4. Моменты: площадь и центр масс

Вывод центра масс

Из физики: если точечные массы mi стоят в точках xi, центр масс

x̄ = Σ mᵢ·xᵢ / Σ mᵢ

Будем считать каждый белый пиксель точкой массы 1, а чёрный — массы 0. Масса пикселя — это значение маски I(x, y) ∈ {0, 1}:

x̄ = Σ x·I(x,y) / Σ I(x,y) ȳ = Σ y·I(x,y) / Σ I(x,y)

Суммы такого вида настолько полезны, что им дали общее имя.

Сырой (геометрический) момент порядка (p, q): mpq = Σx Σy xp·yq·I(x, y).
m00 = Σ I = число белых пикселей = площадь.
m10 = Σ x·I, m01 = Σ y·I.
Центр масс (центроид): x̄ = m10 / m00, ȳ = m01 / m00.

Пример: фигура «Г»

y\x 0 1 2 3
 1  . # . .        белые пиксели: (1,1) (1,2) (1,3) (1,4) (2,4) (3,4)
 2  . # . .
 3  . # . .        m00 = 6
 4  . # # #        m10 = 1+1+1+1+2+3 = 9      x̄ = 9/6  = 1,5
                   m01 = 1+2+3+4+4+4 = 18     ȳ = 18/6 = 3,0

Центр масс (1,5; 3) — не обязательно центр рамки (2; 2,5): масса смещена к длинной «ножке».

Центр масс составной фигуры — взвешенное среднее центров частей: x̄ = (A₁·x̄₁ + A₂·x̄₂) / (A₁ + A₂). Это прямо следует из того, что суммы m00 и m10 можно разбить на части.

M  = cv2.moments(mask, binaryImage=True)   # словарь: m00, m10, m01, m20, m11, m02, ..., mu20, mu11, mu02, ...
cx = M["m10"] / M["m00"]                    # проверяйте M["m00"] > 0, иначе деление на ноль
cy = M["m01"] / M["m00"]
M2 = cv2.moments(contour)                   # то же, но по многоугольнику контура (раздел 6)

5. Центральные моменты и ориентация

Сырые моменты зависят от того, где объект стоит в кадре. Чтобы описывать форму, отсчитываем координаты от центра масс.

Центральный момент: μpq = Σ (x − x̄)p·(y − ȳ)q·I(x, y). Он не меняется при сдвиге объекта. μ20 — разброс по x, μ02 — разброс по y, μ11 — «наклон» (как ковариация).

Вывод через сырые моменты (так их и считают на практике):

μ₂₀ = Σ (x − x̄)²·I = Σ x²I − 2x̄·Σ xI + x̄²·Σ I = m₂₀ − 2x̄·m₁₀ + x̄²·m₀₀ = m₂₀ − 2x̄·m₁₀ + x̄·m₁₀ (т. к. x̄·m₀₀ = m₁₀) = m₂₀ − x̄·m₁₀ аналогично: μ₀₂ = m₀₂ − ȳ·m₀₁ μ₁₁ = m₁₁ − x̄·m₀₁ μ₁₀ = μ₀₁ = 0

Вывод угла главной оси

Главная ось — прямая через центр масс, вдоль которой объект «вытянут». Это прямая, относительно которой момент инерции минимален. Пусть прямая идёт под углом θ, (x′, y′) — координаты пикселя относительно центра. Расстояние до прямой: d = y′·cos θ − x′·sin θ. Момент инерции:

J(θ) = Σ d²·I = μ₀₂·cos²θ − 2μ₁₁·sinθ·cosθ + μ₂₀·sin²θ dJ/dθ = (μ₂₀ − μ₀₂)·sin2θ − 2μ₁₁·cos2θ = 0 ⇒ tan 2θ = 2μ₁₁ / (μ₂₀ − μ₀₂) θ = ½·atan2(2μ₁₁, μ₂₀ − μ₀₂)

atan2 выбирает корень, где J минимален, и не ломается при μ20 = μ02. Проверка в скрипте 03: полоса, нарисованная под углом −36,9°, даёт θ = −36,9° (ось y направлена вниз, поэтому «вверх-вправо» — отрицательный угол).

Насколько вытянут объект — по собственным числам матрицы [[μ₂₀, μ₁₁], [μ₁₁, μ₀₂]]:

λ₁,₂ = ( μ₂₀ + μ₀₂ ± √((μ₂₀ − μ₀₂)² + 4μ₁₁²) ) / 2 вытянутость = √(λ₁/λ₂)

У круга и квадрата λ₁ = λ₂, и направление оси не определено. У линии на полу λ₁ ≫ λ₂, и θ — это направление линии: прямо пригодится для следования по линии (раздел 9).

Инвариантные моменты Ху. Если разделить μpq на m001+(p+q)/2, моменты перестают зависеть от масштаба. Ху (1962) составил из них 7 чисел, которые не меняются ещё и при повороте. cv2.HuMoments(M) и cv2.matchShapes(c1, c2, ...) сравнивают формы «на похожесть» независимо от размера и поворота.

6. Площадь контура: формула шнурования

Контур — многоугольник с вершинами (x₀, y₀), …, (xn−1, yn−1). Его площадь можно посчитать по координатам вершин.

Вывод через трапеции

Каждое ребро от (xᵢ, yᵢ) до (xᵢ₊₁, yᵢ₊₁) вместе с осью x образует трапецию с ориентированной площадью (xᵢ₊₁ − xᵢ)·(yᵢ + yᵢ₊₁) / 2: на одной стороне обхода ширина положительная, на другой отрицательная. Части снаружи фигуры сокращаются, остаётся площадь самой фигуры. Раскроем скобки и сложим по всем рёбрам замкнутого контура:

Σ (xᵢ₊₁yᵢ + xᵢ₊₁yᵢ₊₁ − xᵢyᵢ − xᵢyᵢ₊₁) / 2 члены xᵢ₊₁yᵢ₊₁ − xᵢyᵢ взаимно уничтожаются (контур замкнут), остаётся: A = ½ · | Σ (xᵢ·yᵢ₊₁ − xᵢ₊₁·yᵢ) | (xₙ = x₀, yₙ = y₀)

Название «шнурование» — от того, как перемножаются координаты крест-накрест, если выписать их столбиком. Знак суммы показывает направление обхода; cv2.contourArea(c) возвращает модуль, а cv2.contourArea(c, oriented=True) — со знаком. Это частный случай формулы Грина: A = ½∮(x dy − y dx); по той же формуле Грина cv2.moments(contour) считает моменты многоугольника.

Пример: треугольник (0,0), (4,0), (0,3): 0·0 − 4·0 = 0; 4·3 − 0·0 = 12; 0·0 − 0·3 = 0. A = ½·12 = 6 ✓ (= ½·4·3).

Почему contourArea меньше числа пикселей: теорема Пика

Вершины контура лежат в центрах пикселей, то есть в целых точках решётки. Для многоугольника с вершинами в узлах решётки есть теорема Пика:

A = I + B/2 − 1 I — число узлов строго внутри, B — число узлов на границе

Число пикселей объекта = все узлы внутри и на границе = I + B. Подставляем I = A − B/2 + 1:

пиксели = A + B/2 + 1

Квадрат 5×5: A = 16, B = 16 → 16 + 8 + 1 = 25 ✓. На учебной картинке формула совпала с подсчётом пикселей для всех шести фигур до единицы (скрипт 03). Для больших объектов разница мала, для маленьких — огромна: у квадрата 3×3 contourArea = 4, а пикселей 9.

7. Описание формы

Периметр

cv2.arcLength(c, closed=True) — сумма длин рёбер. Горизонтальный или вертикальный шаг даёт 1, диагональный √2. Из-за «лесенки» пикселей периметр кривых фигур завышается.

Рамки и окружности

ФункцияЧто возвращает
cv2.boundingRect(c)(x, y, w, h) — прямая рамка, стороны параллельны осям кадра
cv2.minAreaRect(c)((cx, cy), (w, h), угол) — повёрнутая рамка минимальной площади; вершины — cv2.boxPoints(rect)
cv2.minEnclosingCircle(c)((cx, cy), r) — минимальная описанная окружность

approxPolyDP (алгоритм Дугласа–Пекера): соединяем первую и последнюю точку отрезком и ищем точку контура, самую далёкую от него. Если расстояние больше ε, делим контур в этой точке надвое и повторяем для каждой половины; если меньше — заменяем весь участок отрезком. ε обычно 1–3% периметра.

Числа, которые описывают форму

ПризнакФормулаСмысл
Соотношение сторон (aspect ratio)w / h рамкивытянутость
Заполненность (extent)A / (w·h)какую долю рамки занимает объект: прямоугольник 1, круг π/4 ≈ 0,785, треугольник 0,5
Выпуклость (solidity)A / Aоболочки1 у выпуклых фигур, меньше — есть «вмятины»
Круглость (circularity)4π·A / P²1 у круга, меньше у остальных

Вывод круглости. Круг: A = πr², P = 2πr ⇒ 4π·πr² / (2πr)² = 4π²r² / 4π²r² = 1. Квадрат: A = a², P = 4a ⇒ 4πa² / 16a² = π/4 ≈ 0,785. Прямоугольник 2:1: A = 2a², P = 6a ⇒ 8π/36 ≈ 0,698. Равносторонний треугольник: A = (√3/4)a², P = 3a ⇒ π√3/9 ≈ 0,605. Больше 1 быть не может: изопериметрическое неравенство 4πA ≤ P² говорит, что из всех фигур с данным периметром наибольшую площадь имеет круг.

На пикселях круглость круга меньше 1. Из-за завышенного периметра цифровой круг радиусом 100 px даёт 0,89, радиусом 20 px — 0,87, радиусом 5 px — 0,76. Пороги подбирайте на своих данных, а маленьким объектам не доверяйте.

8. Ловушки центра масс и площади

  • Центр масс может лежать вне объекта. У кольца он в дырке, у буквы «C» — в пустоте между «рогами». Если робот поедет «в центр масс» подковы, захват сомкнётся на пустоте. Точку внутри объекта даёт, например, максимум cv2.distanceTransform (самая «глубокая» точка маски).
  • RETR_EXTERNAL игнорирует дырки. Площадь кольца по внешнему контуру — это площадь всего диска. Настоящая площадь = внешний контур − дырки (RETR_CCOMP или RETR_TREE). На картинке: 13 090 − 3 952 = 9 138.
  • Моменты маски и моменты контура различаются. cv2.moments(mask) считает пиксели (с учётом дырок), cv2.moments(contour) — площадь многоугольника по центрам граничных пикселей (без дырок). Центры почти совпадают, площади — нет.
  • Самый большой — не всегда нужный. На нашем фото кроме мяча красные костюм и кирпичи. Сейчас мяч самый большой, но если он отъедет, первым станет костюм. Надёжнее фильтровать по форме: круглость мяча 0,88, костюма 0,25.
  • Объект, обрезанный краем кадра, имеет «неправильную» площадь и смещённый центр.

9. Для робота: из центра и площади в команду

Ошибка и регулятор

e = cx − W/2 ошибка в пикселях (+ — объект справа) eₙ = e / (W/2) ∈ [−1, 1] нормированная, не зависит от разрешения ω = −K · eₙ скорость поворота (+ — влево, против часовой) |eₙ| < 0,1 ⇒ ω = 0 «мёртвая зона», чтобы робот не дёргался

Это П-регулятор (пропорциональный): чем дальше объект от центра, тем резче поворот. Если контур не найден, робот переходит в режим поиска (например, медленно крутится на месте).

Расстояние по площади

По модели камеры-обскуры (подробно в уроке 6) размер изображения объекта обратно пропорционален расстоянию: s = f·S/d. Площадь — квадрат размера, значит A ∝ 1/d²:

A·d² = const ⇒ d = d₀ · √(A₀ / A)

Достаточно один раз откалибровать: поставить мяч на известное расстояние d₀ и запомнить его площадь A₀. Площадь в 4 раза меньше — объект в 2 раза дальше. Работает только для одного и того же объекта, видимого целиком и примерно «лицом» к камере.

03_moments_from_scratch.py — Моменты с нуля, ориентация, шнурование, теорема Пика
"""Моменты с нуля: площадь, центр масс, ориентация. Формула шнурования. Сверка с OpenCV."""
from pathlib import Path
import cv2
import numpy as np


def raw_moment(mask, p, q):
    ys, xs = np.nonzero(mask)                    # координаты белых пикселей: x - столбец, y - строка
    return float(np.sum(xs.astype(float) ** p * ys.astype(float) ** q))


def shoelace(pts):
    """Площадь многоугольника по вершинам (формула Гаусса, «шнурование»). Знак = направление обхода."""
    x, y = pts[:, 0].astype(float), pts[:, 1].astype(float)
    return 0.5 * np.sum(x * np.roll(y, -1) - np.roll(x, -1) * y)


# 1) Маленькая «Г»-образная фигура: считаем руками
L = np.zeros((6, 6), np.uint8)
L[1:5, 1] = 1; L[4, 2:4] = 1
print("Г-фигура:\n", L)
m00, m10, m01 = raw_moment(L, 0, 0), raw_moment(L, 1, 0), raw_moment(L, 0, 1)
print(f"m00={m00:.0f}  m10={m10:.0f}  m01={m01:.0f}  центр масс=({m10/m00:.2f}, {m01/m00:.2f})")
cvm = cv2.moments(L, binaryImage=True)
print("OpenCV:", {k: cvm[k] for k in ("m00", "m10", "m01")})

# 2) Ориентация через центральные моменты
bar = np.zeros((60, 60), np.uint8)
cv2.line(bar, (10, 50), (50, 20), 1, 5)               # наклонная полоса
m = cv2.moments(bar, binaryImage=True)
cx, cy = m["m10"] / m["m00"], m["m01"] / m["m00"]
mu20 = raw_moment(bar, 2, 0) - cx * m["m10"]           # mu20 = m20 - x̄·m10
mu02 = raw_moment(bar, 0, 2) - cy * m["m01"]
mu11 = raw_moment(bar, 1, 1) - cx * m["m01"]

"""Трекер цветного объекта с веб-камеры: ползунки HSV, центр масс, ошибка и команда. ESC или q - выход.

import cv2
import numpy as np

cap = cv2.VideoCapture(0)

WIN = "tracker"
cv2.namedWindow(WIN)

                      ("min area", 500, 5000)]:

    ok, frame = cap.read()

        frame = still.copy()

        cv2.putText(frame, f"e={e:+.2f} area={cv2.contourArea(c):.0f} {cmd}", (10, 30),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.7, (0, 255, 255), 2)

    if cv2.waitKey(30) & 0xFF in (27, ord("q")):

from pathlib import Path

cv2.line(vis, (W // 2, 0), (W // 2, H), (255, 255, 255), 1)

fig, ax = plt.subplots(1, 2, figsize=(12, 4.8))
ax[0].imshow(mask, cmap="gray"); ax[0].set_title("маска линии (THRESH_BINARY_INV)")
ax[1].imshow(cv2.cvtColor(vis, cv2.COLOR_BGR2RGB)); ax[1].set_title("центры в полосах (красный - ближняя)")
for a in ax:
    a.axis("off")
