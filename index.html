1. Изображение как матрица

Пиксель — минимальная ячейка изображения, одно число (ЧБ) или набор из трёх чисел (цвет). Изображение — прямоугольная таблица пикселей, то есть массив NumPy. Канал — один «слой» таких чисел (например, только красные значения). dtype — тип чисел; в OpenCV почти всегда uint8, то есть целые от 0 до 255.

Чёрно-белое: 2 измерения, (H, W)

Одно число на пиксель: 0 — чёрный, 255 — белый. Фрагмент 4×4:

04080120
4080120160
80120160200
120160200255

Для фото 640×840 (высота × ширина) img.shape даст (640, 840).

Цветное: 3 измерения, (H, W, 3)

В каждой ячейке тройка чисел. Картинку 2×2 можно представить как три матрицы 2×2, наложенные друг на друга:

Слой BСлой GСлой R
0 0
255 0		0 255
0 0		255 0
0 0

Здесь пиксель (0,0) чисто красный, (0,1) зелёный, (1,0) синий, (1,1) чёрный. В коде это img[0,0] → [0, 0, 255] (порядок B, G, R, см. раздел 3). Shape такой картинки (2, 2, 3).

Порядок индексов. Пиксель берётся как img[y, x]: сначала строка (высота), потом столбец (ширина). А вот cv2.resize принимает размер как (ширина, высота). Это источник множества ошибок.

3. RGB и BGR

RGB — аддитивная модель: цвет получается сложением красного, зелёного и синего света, каждый канал 0–255. (0,0,0) чёрный, (255,255,255) белый, (255,0,0) красный, (255,255,0) жёлтый.
BGR — те же три канала, но в обратном порядке: синий, зелёный, красный. OpenCV хранит и читает картинки именно в BGR (историческая особенность библиотеки).

Один и тот же красный пиксель: в RGB это [255, 0, 0], в OpenCV [0, 0, 255]. Если показать BGR-массив через matplotlib (он ждёт RGB), красное становится синим:

Переключение: rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB).

4. HSV

HSV разделяет цвет на три понятных величины: H (Hue, оттенок) — «какой это цвет»; S (Saturation, насыщенность) — «насколько он яркий и чистый» (0 — серый или белый); V (Value, яркость) — «насколько светло» (0 — чёрный).

Диапазоны в OpenCV: H = 0–179 (градусы цветового круга, делённые на 2, чтобы значение влезло в uint8), S = 0–255, V = 0–255.

0 красный30 жёлтый60 зелёный90 голубой120 синий150 фиолет.179 красный

Красный лежит на обоих концах шкалы, поэтому для него нужны два диапазона.

ЦветRGBHSV (OpenCV)
красный255,0,00, 255, 255
жёлтый255,255,030, 255, 255
зелёный0,255,060, 255, 255
синий0,0,255120, 255, 255
белый255,255,2550, 0, 255
серый128,128,1280, 0, 128
чёрный0,0,00, 0, 0

Обратите внимание: у серого, белого и чёрного H равен 0 «формально», у них оттенка нет. Поэтому при малых S и V значению H доверять нельзя.

5. Конвертации

В чёрно-белое

gray = 0.299·R + 0.587·G + 0.114·B. Веса разные, потому что глаз сильнее всего чувствителен к зелёному.

RGB → HSV

Пусть R, G, B в диапазоне 0–1, max и min — наибольший и наименьший из них, Δ = max − min.

V = max
S = Δ / max            (если max = 0, то S = 0)
H = 60 · ((G − B) / Δ)       если max = R   (если вышло < 0, прибавить 360)
H = 60 · (2 + (B − R) / Δ)   если max = G
H = 60 · (4 + (R − G) / Δ)   если max = B
# в OpenCV: H/2, S·255, V·255
Разобранный пример. Пиксель шара (RGB 238, 76, 117): max = 238 (R), min = 76, Δ = 162. V = 238. S = 162/238 = 0,68, то есть 174. H = 60·((76−117)/162) = −15,2, +360 = 344,8, делим на 2: 172. Скрипт из раздела 7 выдаёт то же самое: [172 174 238].

6. Почему RGB не подходит для фильтрации по цвету

В RGB цвет и яркость перемешаны во всех трёх каналах. Красный предмет на свету и в тени даёт, например, (220, 40, 40) и (90, 15, 15): все три числа поменялись. Область «красного» в RGB — сложная форма, а не прямоугольник из трёх min/max. В HSV оттенок лежит в одном канале H и почти не зависит от освещения, поэтому «красный» превращается в простое условие: узкий H, S и V не слишком маленькие.

Но HSV не волшебство. 1) Красный требует двух диапазонов. 2) При малых S и V канал H шумит (серые, белые и тёмные пиксели). 3) Цветное освещение сдвигает H. 4) Фильтр ловит все объекты нужного цвета, а не «объект».

7. Демо-код

Демо 1: цветовые пространства и размеры матриц

import cv2
import matplotlib.pyplot as plt

img  = cv2.imread("cat.jpg")                     # BGR
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
rgb  = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
hsv  = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

for name, m in [("gray", gray), ("bgr", img), ("rgb", rgb), ("hsv", hsv)]:
    print(name, m.shape, m.ndim, m.dtype, m.min(), m.max())

y, x = 420, 140                                   # точка на шаре
print("BGR", img[y, x], "RGB", rgb[y, x], "HSV", hsv[y, x])

fig, ax = plt.subplots(1, 4, figsize=(16, 6))
ax[0].imshow(gray, cmap="gray"); ax[1].imshow(rgb)
ax[2].imshow(img);               ax[3].imshow(hsv)
plt.show()

Демо 2: фильтр по цвету

import cv2, numpy as np
img = cv2.imread("cat.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

lower = np.array([20, 100, 100])    # H, S, V (минимум)
upper = np.array([35, 255, 255])    # H, S, V (максимум)
mask   = cv2.inRange(hsv, lower, upper)          # 255 там, где цвет подошёл
result = cv2.bitwise_and(img, img, mask=mask)    # оставить только подошедшее
print("пикселей:", cv2.countNonZero(mask))

cv2.imshow("mask", mask); cv2.imshow("result", result)
cv2.waitKey(0)

Красный: два диапазона

m1  = cv2.inRange(hsv, np.array([0, 120, 70]),   np.array([10, 255, 255]))
m2  = cv2.inRange(hsv, np.array([170, 120, 70]), np.array([179, 255, 255]))
red = cv2.bitwise_or(m1, m2)

8. Практика: матрица 5×5 в HSV

Шаг 1 (на бумаге). Распечатайте или перерисуйте матрицу ниже (в каждой ячейке H, S, V). По условию определите, какие ячейки пройдут фильтр. Шаг 2. Здесь же: кликайте ячейки, которые считаете подходящими, и нажмите «Проверить». Шаг 3. Перенесите диапазон в скрипт (inRange) и сравните.

Если H min больше H max, диапазон «заворачивается» через 179→0 (так ловится красный, в коде это два inRange и bitwise_or). Границы включительно.

Что проверяет матрица: граничные значения (H = 35, 85; S = 100), серые пиксели с «подходящим» H (S около 0), тёмные пиксели с подходящим H (V около 10), красные ячейки с H = 5 и 175.

Задачи для скрипта и страницы: 1) подберите границы, чтобы осталась только одна цветовая группа; 2) выделите ровно 6 ячеек; 3) выделите все красные; 4) выделите все «тёмные», не трогая H и S.

10. Типичные ошибки и шпаргалка

  • imread вернул None: неверный путь.
  • Цвета «перепутаны»: BGR против RGB.
  • Окно сразу закрылось: нет waitKey(0).
  • img[x, y] вместо img[y, x].
  • H задан до 360: в OpenCV максимум 179.
  • Красный не ловится: нужны два диапазона.
  • Серые и тёмные пиксели «шумят»: поднимите нижние границы S и V.
