1. Зачем размывать картинку

Камера робота никогда не даёт идеальную картинку. Каждый кадр содержит шум — случайные отклонения яркости, которых нет в реальной сцене. Если сразу сделать маску по цвету или порог, шум превратится в сотни мелких «мусорных» пятен, и робот начнёт видеть объекты там, где их нет. Блюр (размытие) усредняет пиксель с соседями и гасит этот шум.

Шум — случайная ошибка в значениях пикселей. Два главных вида:
Гауссов шум: каждый пиксель немного «дрожит» вокруг правильного значения (зернистость в темноте, дешёвая камера).
Импульсный шум («соль и перец»): отдельные пиксели становятся совсем белыми или чёрными (битые пиксели, помехи при передаче видео).

Цена блюра: вместе с шумом размываются и мелкие детали и границы. Поэтому вид фильтра и его размер выбирают под задачу (раздел 7).

2. Свёртка: идея и вычисление

Ядро (kernel) — маленькая матрица весов, обычно 3×3, 5×5, 7×7. Размер нечётный, чтобы у ядра был центр.
Окрестность пикселя — квадрат того же размера, что ядро, с этим пикселем в центре.
Свёртка — операция, при которой ядро «проезжает» по картинке; в каждой позиции веса ядра поэлементно умножаются на пиксели окрестности, произведения складываются, и сумма становится новым значением центрального пикселя.

Формула для ядра 3×3 (индексы i, j от −1 до 1):

out(y, x) = Σ Σ  K(i, j) · I(y + i, x + j)

Пример: окрестность и ядро box 3×3 (все веса по 1/9, то есть простое среднее):

(10+20+30+40+50+60+70+80+90) / 9 = 450 / 9 = 50. Это новое значение центрального пикселя. Важно: при сдвиге окна берутся исходные значения, а не уже посчитанные, поэтому результат пишут в новую матрицу.

Терминологическая тонкость. В математике при свёртке ядро сначала переворачивают на 180°, а без переворота операция называется корреляцией. cv2.filter2D на самом деле делает корреляцию. Для всех ядер размытия это неважно: они симметричны, и переворот ничего не меняет. В компьютерном зрении обе операции обычно называют свёрткой.

Свёртка в коде

def conv2d(img, kernel):
    k = kernel.shape[0]; r = k // 2
    padded = np.pad(img.astype(np.float32), r, mode="reflect")   # рамка, см. раздел 3
    out = np.zeros(img.shape, np.float32)
    for y in range(img.shape[0]):
        for x in range(img.shape[1]):
            out[y, x] = (padded[y:y+k, x:x+k] * kernel).sum()  # умножить и сложить
    return out

out = cv2.filter2D(img, -1, kernel)      # то же самое в OpenCV (в сотни раз быстрее)

На фото 663×462 учебная версия с циклами работает около секунды, а OpenCV за миллисекунды. Поэтому «с нуля» пишем для понимания, а в роботе используем OpenCV.

3. Что делать на краях: размер выхода и рамка

У пикселя на краю картинки нет части соседей. Два варианта:

1. Без рамки (valid). Считаем только там, где окно целиком помещается. Картинка уменьшается: при ядре k×k выход будет (H − k + 1) × (W − k + 1). Ядро 3×3 «съедает» по одному пикселю с каждой стороны.

2. С рамкой (padding). Картинку заранее дополняют рамкой шириной k // 2, и выход того же размера, что вход. OpenCV делает так по умолчанию. Виды рамки для строки 1 2 3 4 и рамки в 2 пикселя:

ВидOpenCVРезультат
нулямиBORDER_CONSTANT0 0 | 1 2 3 4 | 0 0
повтор краяBORDER_REPLICATE1 1 | 1 2 3 4 | 4 4
отражениеBORDER_REFLECT2 1 | 1 2 3 4 | 4 3
отражение без края (по умолчанию)BORDER_REFLECT_1013 2 | 1 2 3 4 | 3 2

Рамка из нулей делает края результата темнее (в среднее подмешиваются чёрные пиксели), поэтому по умолчанию используют отражение. В NumPy это np.pad(img, r, mode="reflect").

4. Разные ядра: что они делают

Нормировка. Если сумма весов ядра равна 1, средняя яркость картинки не меняется. Сумма больше 1 делает картинку светлее (вплоть до белого 255), меньше 1 делает темнее. Все ядра размытия нормируют.

Главный вывод: свёртка — универсальный инструмент. Одна и та же операция в зависимости от весов ядра размывает, сдвигает или подчёркивает детали. Свёрточные нейросети учатся подбирать эти веса сами.

5. Виды блюра

5.1. Box blur (усредняющий)

Каждый пиксель заменяется средним по окну k×k, все соседи равноправны. cv2.blur(img, (k, k))

Плюсы: самый быстрый, скорость почти не зависит от размера ядра. Минусы: далёкие соседи весят столько же, сколько ближние, поэтому размытие грубое, «квадратное», края расплываются сильнее всего; выброс не исчезает, а размазывается по окну. Когда: нужно очень быстро и грубо сгладить, например на слабом железе.

5.2. Gaussian blur (гауссов)

Взвешенное среднее: чем ближе сосед к центру, тем больше его вес. Веса берутся из функции Гаусса G(x, y) = exp(−(x² + y²) / 2σ²) и нормируются. cv2.GaussianBlur(img, (k, k), sigma)

σ (sigma) — сила размытия: чем больше σ, тем «шире колокол» и сильнее размытие. Если передать sigma=0, OpenCV вычислит её из размера ядра: σ = 0.3·((k − 1)·0.5 − 1) + 0.8. Размер ядра должен быть нечётным.

Разделимость. Гауссово ядро равно произведению столбца на строку: [1 2 1]ᵀ · [1 2 1] = [[1,2,1],[2,4,2],[1,2,1]]. Значит, можно сначала размыть по строкам одномерным ядром, потом по столбцам. Для ядра k×k это 2k операций на пиксель вместо k²: для 7×7 это 14 вместо 49.

Когда: стандартный выбор против гауссова шума и обязательная предобработка перед поиском границ (Canny, урок 4) и перед порогом.

5.3. Median blur (медианный)

Пиксель заменяется медианой значений в окне: значения сортируются и берётся среднее по порядку (для окна 3×3 это 5-е из 9). cv2.medianBlur(img, k)

Это не свёртка: нет весов, нет умножения и сложения, это нелинейная операция. Поэтому свойства у неё другие:

  • Выбросы исчезают полностью. Один белый пиксель среди тёмных окажется в конце сортировки и в медиану не попадёт, а среднее его бы размазало.
  • Края сохраняются. На границе тёмного и светлого медиана выбирает одну из сторон, а не серое «между».
  • Минусы: медленнее box и gauss при большом k; тонкие линии толщиной 1–2 пикселя и острые углы исчезают (важно для следования по линии).

Когда: импульсный шум («соль-перец»), битые пиксели, одиночный мусор. k нечётное; для uint8 любое, для других типов только 3 или 5.

5.4. Bilateral filter (билатеральный)

Взвешенное среднее, где вес соседа зависит от двух вещей: расстояния до центра (как у Гаусса) и похожести по яркости. Сильно отличающиеся соседи (по ту сторону границы) почти не учитываются. cv2.bilateralFilter(img, d, sigmaColor, sigmaSpace)

Плюсы: сглаживает однородные области, сохраняя чёткие границы. Минусы: медленный, плохо подходит для потока с камеры на слабом железе; против «соли-перца» почти бесполезен: выброс сильно отличается от соседей, фильтр считает его «границей» и не трогает. Когда: нужна гладкость без потери краёв и есть запас по времени.

6.2. 1D-медиана на картинке

Окно медианы не обязано быть квадратом. Можно взять отрезок: k пикселей подряд в строке (горизонтальная 1D-медиана) или в столбце (вертикальная). Тогда каждая строка или каждый столбец картинки обрабатывается как отдельный 1D-сигнал из раздела 6.1.

Что видно:

  • «Соль-перец» (верхний ряд). Даже медиана только по строкам с k = 5 убирает почти все точки: одиночный выброс в отрезке из пяти всегда в меньшинстве.
  • Большое окно k = 31 (средний ряд). 1D-медиана рисует «мазки» вдоль своей оси: горизонтальные полосы при обработке строк и вертикальные при обработке столбцов, похоже на смаз от движения. Строки → столбцы даёт «живописный» эффект, похожий на 2D-медиану.
  • Тонкие линии (нижний ряд). Направление решает всё. Медиана по строкам сохраняет горизонтальные линии (вдоль окна линия — это «большинство») и стирает вертикальные (поперёк окна линия — одиночный выброс, задание 16). По столбцам наоборот. Строки → столбцы и 2D-медиана стирают обе.

Строки → столбцы — это не то же самое, что 2D-медиана. На нашем фото при k = 5 совпадает около 55% пикселей, хотя в среднем разница всего около 1 уровня яркости. Зато считается намного быстрее: на каждый пиксель сортируется 2k значений вместо k². В NumPy при k = 15 это было примерно в 20 раз быстрее. Сравните с гауссом (раздел 5.2): там разделение на строки и столбцы даёт точно тот же результат, потому что свёртка линейна, а медиана нелинейна, и разделение даёт только приближение.

Практическая польза: если шум или помехи вытянуты в одном направлении (например, строчные помехи при передаче видео), или нужно сохранить линии известного направления, 1D-медиана поперёк них подходит лучше квадратного окна.

from numpy.lib.stride_tricks import sliding_window_view
def median_1d(img, k, axis):                 # axis=1: по строкам, axis=0: по столбцам
    pad = [(0, 0)] * img.ndim
    pad[axis] = (k // 2, k // 2)
    padded = np.pad(img, pad, mode="edge")
    windows = sliding_window_view(padded, k, axis=axis)   # добавилась ось окна длины k
    return np.median(windows, axis=-1).astype(img.dtype)

rows  = median_1d(img, 5, axis=1)
both  = median_1d(rows, 5, axis=0)           # строки -> столбцы

from numpy.lib.stride_tricks import sliding_window_view
def median2d(img, k=3):
    padded = np.pad(img, k // 2, mode="edge")             # как BORDER_REPLICATE
    windows = sliding_window_view(padded, (k, k))         # окно k×k для каждого пикселя
    return np.median(windows, axis=(-2, -1)).astype(img.dtype)
# совпадает с cv2.medianBlur(img, k) пиксель в пиксель

7. Какой блюр когда нужен

СитуацияФильтрПочему
Зернистость, тусклый свет, дешёвая камераGaussian 3–5шум «мелкий и везде», взвешенное среднее гасит его мягко

Сгладить, но сохранить чёткие края, время естьBilateralне усредняет через границу

Размер ядра — главный компромисс: больше ядро — сильнее подавление шума, но больше теряется деталей и медленнее. Начинайте с 3 или 5. Скорость (от быстрого к медленному): box → gauss → median → bilateral.

01_convolution_from_scratch.py — Свёртка с нуля и сверка с cv2.filter2D
"""Свёртка с нуля на NumPy и сравнение с cv2.filter2D."""
from pathlib import Path
import time
import cv2
import numpy as np


def conv2d_loops(img, kernel, pad="reflect"):
    """Учебная версия: два цикла по пикселям. pad="valid" - без рамки, картинка уменьшится."""
    k = kernel.shape[0]
    r = k // 2
    src = img.astype(np.float32)
    padded = src if pad == "valid" else np.pad(src, r, mode=pad)   # "reflect" = BORDER_REFLECT_101
    H, W = padded.shape[0] - k + 1, padded.shape[1] - k + 1
    out = np.zeros((H, W), np.float32)
    for y in range(H):
        for x in range(W):
            window = padded[y:y + k, x:x + k]          # окрестность k×k
            out[y, x] = (window * kernel).sum()         # поэлементно умножить и сложить
    return out


def conv2d_fast(img, kernel):
    """Быстрая версия: цикл по элементам ядра, а не по пикселям (k*k сдвинутых копий)."""
    k = kernel.shape[0]
    r = k // 2
    padded = np.pad(img.astype(np.float32), r, mode="reflect")
    H, W = img.shape
    out = np.zeros((H, W), np.float32)
    for i in range(k):
        for j in range(k):
            out += kernel[i, j] * padded[i:i + H, j:j + W]
    return out

05_median_1d_image.py — 1D-медиана на 2D-картинке: строки, столбцы, строки → столбцы
"""1D-медиана на 2D-картинке: окно - отрезок строки или столбца, а не квадрат.
Сравниваем: только по строкам, только по столбцам, строки -> столбцы и настоящую 2D-медиану."""
from pathlib import Path
import time
import cv2
import numpy as np
import matplotlib.pyplot as plt
from numpy.lib.stride_tricks import sliding_window_view


def median_1d(img, k, axis):
    """Медиана по отрезку длины k вдоль оси axis (1 - по строкам, 0 - по столбцам).
    Работает и для ЧБ (H, W), и для цветной (H, W, 3) картинки."""
    pad = [(0, 0)] * img.ndim
    pad[axis] = (k // 2, k // 2)
    padded = np.pad(img, pad, mode="edge")                  # повтор края
    windows = sliding_window_view(padded, k, axis=axis)     # к форме добавилась ось окна длины k
    return np.median(windows, axis=-1).astype(img.dtype)


def rows_then_cols(img, k):
    return median_1d(median_1d(img, k, axis=1), k, axis=0)

from pathlib import Path
import cv2
import numpy as np
from numpy.lib.stride_tricks import sliding_window_view


def median2d(img, k=3):
    """Медиана по окну k×k. Рамка копирует крайние пиксели (как BORDER_REPLICATE в OpenCV)."""
    padded = np.pad(img, k // 2, mode="edge")

    return np.median(windows, axis=(-2, -1)).astype(img.dtype)
